# Audit G — Rewards and Gameplay Loops

## G1 Reward rule
Every repeatable activity must answer: what does it reward, where is that reward used, and what player choice does that use create?

## Canonical loop types
Explore -> resource/discovery -> building/equipment/content.
Combat -> component/reward -> transmutation/equipment -> new combat choices.
Community -> stable output/opportunity -> specialization/content.
Quest -> unique unlock/change -> narrative/system expansion.

## G2 Anti-orphan rules
No recurring resource without a consumption destination; no major building without a source of value; no repeatable activity whose rewards are consistently obsolete; no reward family used only as generic currency unless explicitly intended.

## Balancing principle
Overlap reward pools enough to prevent mandatory farming, while preserving distinct identities for activities.

## Pending decisions
Currency architecture; duplicate reward conversion/sinks; catch-up mechanisms; obsolete-equipment handling; whether any activity has exclusive rewards.
