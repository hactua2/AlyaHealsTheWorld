# Rewards and Gameplay Loops

Every repeatable activity must define:
1. reward produced;
2. consumption destination;
3. player choice enabled by that destination.

## Canonical loops
Explore -> ResourceOrDiscovery -> BuildingOrEquipmentOrContent.
Combat -> ComponentOrReward -> ModificationOrEquipment -> NewCombatChoices.
Community -> StableOutputOrOpportunity -> SpecializationOrContent.
Quest -> UniqueUnlockOrStateChange -> NarrativeOrSystemExpansion.

## Validation rules
- recurring resources require at least one sink;
- major buildings require a value source;
- repeatable activities should not become universally obsolete without replacement;
- avoid forcing a single activity for every resource;
- reward pools may overlap while preserving activity identity.

Quest reward hints should expose major categories without revealing every hidden reward, branch, or consequence.
